### 배운 점
- 401 + `GRANT … TO anon` 힌트는 키가 공개용(publishable/anon)으로 인식됐다는 뜻이다. RLS·권한 회수가 의도대로 막고 있다는 확인이기도 하다.
- pgvector가 `extensions` 스키마에 있어 조회에서 `vector_dims`·`<=>`는 스키마를 붙이거나 `search_path`에 `extensions`를 넣어야 한다.
- SQL Editor는 열려 있는 프로젝트와 선택 영역 기준으로 실행된다. 실행 뒤에는 반드시 다른 경로(MCP 조회)로 반영을 확인한다.
- 터미널에서 긴 SQL을 복사하면 줄이 빠질 수 있다. 실행할 SQL은 파일로 두고 파일에서 복사한다.
- 새 publishable/secret 키는 JWT가 아니라 플랫폼 `verify_jwt`를 통과하지 못한다. 함수 쪽에서 `SUPABASE_SECRET_KEYS`(JSON, `default`)를 기본 제공한다.
- 임베딩 유사도는 같은 주제(고령자·집)의 문서 밖 질문에도 높게 나온다. 하한 하나로 "문서에 없음"을 가르기 어렵고, 생성 단계의 고정 문구가 실제로 막아 준다.
- `!` 명령의 출력은 대화 기록에 남는다. 비밀값은 `| clip`처럼 화면에 내지 않는 방법으로 만든다.
- `loading="lazy"` 이미지는 앵커 스크롤 뒤에 로드되며 위치를 밀어낸다. 느린 네트워크로 재현해야 보인다.
- 요청 상한이 작을 때는 `fetch`를 흉내 내 화면 동작을 확인하고, 실제 요청은 꼭 필요한 것만 보낸다. 같은 IP의 다른 사용(직접 사용)도 같은 상한을 쓴다.

### 배운 점 / 결정 근거
- **실측하지 않은 수치는 결과처럼 쓰지 않는다.** 합성 신호 결과도 조건과 "실제 영상 측정 전"을 함께 표시해야 오해가 없음.
- **판단은 위치 + 자세 두 축.** "시야 밖"은 외출이 아니고, 외출은 현관 센서가 근거일 때만 추정 — 홈페이지·PRD·코드의 표현을 같은 규칙으로 맞춤.
- **GitHub Pages는 `.md`를 렌더링하지 않는다.** 문서를 홈페이지 안에서 보여 주려면 뷰어가 필요하고, 상대 경로는 문서 위치 기준으로 다시 계산해야 이미지가 깨지지 않음.
- **가정은 가정으로 남긴다.** 문서를 쓰다 보면 그럴듯한 기능(야간 조명)이나 세부 설정(나이·지역·직업)이 덧붙는데, 근거 없는 내용은 정리하고 전제가 필요한 기능은 "(돌봄 기관 도입 시)"처럼 조건을 붙여 남김.
- **문서와 홈페이지는 함께 고친다.** PRD를 바꾸면 홈페이지에서 관련 단어를 검색해 남은 곳이 없는지 숫자로 확인.
- **커밋 범위를 좁게 유지.** 작업마다 필요한 파일만 스테이징하고, 커밋 전후 `git status`로 다른 변경이 섞이지 않았는지 확인.
