# 별일없지 — 모델 선택 · 학습 · 검증 계획

> 문서 버전 v1.0 · 작성일 2026-10-08
> 관련 문서: [PRD](../PRD/PRD.md) · [Vision 전처리·후처리 설계](vision-preprocessing-design.md)

> **현재 상태:** 이 문서는 **계획**입니다. 모델 학습과 검증은 아직 진행하지 않았습니다.
> 지금까지 한 것은 모델 선택과 근거 정리, 사전학습 모델을 쓰는 파이프라인 코드 작성(가짜 입력으로 로직 테스트 18개 통과)까지입니다. 진행 상황은 6장에 따로 정리했습니다.

## 1. 별일없지에서 AI가 하는 일

별일없지의 카메라 AI는 "사람이 **무엇을 하는지**"를 직접 맞히지 않습니다. 모델은 **사람이 어디에 있는지(박스)와 관절 위치**만 찾고, 생활 상태는 그 결과를 위치·자세·체류 시간으로 조합해서 규칙으로 판단합니다.

| 단계 | 담당 | 하는 일 | 다루는 문서 |
|---|---|---|---|
| 1 | 카메라 · 전처리 | 영상 입력, 샘플링, 밝기 보정 | [전처리·후처리 설계](vision-preprocessing-design.md) |
| 2 | **AI 모델** | 사람 검출 · 관절 추정 | **이 문서** |
| 3 | 후처리 규칙 | 위치(Zone) + 자세 + 체류 시간 → 생활 이벤트 | [전처리·후처리 설계](vision-preprocessing-design.md) |

그래서 모델이 풀어야 할 문제는 **"화면 속 사람을 놓치지 않고, 사람이 아닌 것을 사람으로 착각하지 않는 것"** 하나로 좁혀집니다. 클래스는 `person` 하나입니다.

## 2. 적합한 모델

### 2.1 선택: YOLO26n

| 판단 기준 | 별일없지의 조건 | 결론 |
|---|---|---|
| 찾을 대상 | 사람 1개 클래스 | 객체 검출 모델, 클래스 1개 |
| 실행 위치 | 영상을 집 밖으로 보내지 않으므로 **집 안의 소형 기기**(노트북 → Raspberry Pi)에서 실행 | 가장 작은 **n** 크기 |
| 필요한 속도 | 판단 단위가 분 단위라 초당 5~10프레임이면 충분 | 정확도보다 가벼움 우선 |
| 데이터 양 | 직접 녹화한 영상뿐, 많아야 수천 장 | 큰 모델은 남는 용량으로 데이터를 외움(과적합) |
| 사전학습 | COCO에 `person` 클래스가 이미 있음 | 전이 학습으로 시작 |

다음 원칙을 따릅니다.
- **"n으로 시작 → 정체되면 s → 그다음 m"**
- **"크기를 올렸는데 성능이 안 오르면 문제는 모델이 아니라 데이터"**
- "성능 좋게 하려고 x 모델을 쓰는 것"은 데이터가 그릇을 채우지 못하면 거의 항상 손해

### 2.2 비교 후보: 자세 추정을 어떻게 붙일 것인가

생활 상태 판단에는 관절 위치(어깨·엉덩이·무릎·발목)가 필요합니다. 두 구성을 같은 영상으로 비교해서 최종 선택합니다.

| 후보 | 구성 | 장점 | 단점 |
|---|---|---|---|
| **A** | YOLO26n(사람 검출) → 사람 영역 crop → MediaPipe Pose(관절 33점) | 화면에 작게 찍힌 사람도 관절이 정확 | 모델 2개를 돌려 느림 |
| **B** | YOLO26n-pose 단독 (검출 + 관절 17점) | 모델 1개라 빠름, 소형 기기에 유리 | 작게 찍힌 사람의 관절 정확도가 낮을 수 있음 |

**선택 기준:** B가 A보다 자세 판정 정확도에서 크게 뒤지지 않으면서 처리 속도가 목표(초당 5프레임 이상)를 만족하면 B, 아니면 A를 선택합니다. 두 후보 모두 판단에 필요한 관절(어깨·엉덩이·무릎·발목)을 제공합니다.

## 3. 학습 계획

### 3.1 핵심 원칙: 학습이 필요한지부터 확인한다

COCO에는 이미 `person`이 있어서, **사전학습 모델이 학습 없이도 사람을 잘 찾을 수 있습니다.** 그래서 무조건 학습부터 하지 않습니다.

1. **기준선 측정:** 학습 없이 `yolo26n.pt`를 우리 검증 데이터로 평가 (4장의 방법)
2. **판단:** 핵심 장면(누움·가려짐·저녁 조명)의 Recall이 목표(0.90, 가정)에 못 미치는 장면이 있을 때만 파인튜닝
3. **파인튜닝:** 약한 장면의 데이터를 보강해 학습
4. **재측정:** 같은 검증 데이터로 기준선과 비교

기준선이 이미 충분하면 "**학습하지 않기로 했다**"도 정당한 결론이며, 그 근거(기준선 결과표)를 남깁니다.

### 3.2 예상되는 약점 장면 (도메인 차이)

COCO 사진과 집 안 고정 카메라 영상은 다음 장면에서 차이가 날 가능성이 높습니다.

| 장면 | 예상 문제 | 서비스 영향 |
|---|---|---|
| 누워 있는 사람 (소파·침대·바닥) | COCO에는 서 있는 사람 사진이 훨씬 많아 놓칠 수 있음 | 바닥에 오래 누운 상태를 놓치면 가장 위험 |
| 가려진 사람 (조리대·식탁 뒤, 이불 속) | 몸 일부만 보여 검출 실패 | 주방 활동이 "시야 밖"으로 기록됨 |
| 저녁 조명, 역광 | 어두워 검출 신뢰도 하락 | 저녁 활동 누락 |
| 침실 IR(흑백) 영상 | 픽셀 통계가 컬러 사진과 다름 | 수면 추정 불가 (로드맵 2단계) |
| TV·거울·액자 속 사람 | 사람이 아닌데 사람으로 검출 | 혼자 계신데 "활동 중"으로 기록 |

### 3.3 데이터 준비

| 항목 | 계획 |
|---|---|
| 수집 | 실제 설치 위치에 카메라(또는 폰)를 고정하고 시나리오별로 녹화 |
| 프레임 추출 | 초당 1~2장만 추출. 연속 프레임은 거의 같은 사진이라 많이 뽑아도 의미가 없음 |
| 규모 (목표, 가정) | 학습용 약 1,000~1,500장, 검증용·시험용 각 약 300장 |
| 클래스 | `person` 1개 |
| 배경 이미지 | TV·거울이 나오는 프레임, 사람이 없는 프레임을 **라벨 없이** 약 10% 포함해 "이건 사람이 아니다"를 학습 |
| 라벨링 도구 | 집 안 영상이므로 클라우드가 아닌 **로컬 도구**(CVAT, Label Studio) |
| 분할 | **녹화 세션(날짜) 단위**로 학습 / 검증 / 시험 분리 (4.1 참고) |
| 개인정보 | 촬영 대상의 동의를 받고, 학습·검증이 끝난 원본 영상은 삭제 |

`data.yaml` 예:

```yaml
path: datasets/byeol-home
train: images/train
val: images/val
test: images/test
names:
  0: person
```

### 3.4 학습 설정

| 설정 | 값 | 근거 |
|---|---|---|
| 시작 가중치 | `yolo26n.pt` | 전이 학습: 사전학습이 사는 것은 정확도가 아니라 **시간** |
| 클래스 이름 | `person` (COCO와 동일) | 클래스 별칭 동기화: 같은 개념이면 분류 가중치까지 이어받음 |
| freeze | 컬러 영상 `10` | 소규모 + 유사 도메인 → 백본 특징 유지, 학습 파라미터 경감 |
| IR 영상 | 2단계 파인튜닝 검토 | 데이터가 적고 도메인이 다르면 1단계(헤드만) → 2단계(전체, lr0 0.001 이하) |
| epochs / patience | `300` / `15` | 300으로 시작, 파인튜닝은 빨리 수렴하므로 patience 10~20 |
| batch | `-1` | VRAM에 맞춰 자동으로 최대치 |
| cache | `True` | 디스크 대기 제거 (2에폭째부터 효과) |
| amp | 기본값(`True`) 유지 | 정확도 손실 없이 빠르고 VRAM 절약, 끄지 않음 |
| optimizer | 기본 `auto`, **lr0를 바꿀 때는 반드시 명시** | 흔한 함정: `auto`는 lr0를 덮어씀 |
| warmup_epochs | `3` (기본값) | 잘 학습된 가중치가 첫 배치에 흐트러지지 않게 |
| imgsz | `640` | 카메라 해상도가 하나 |
| multi_scale | 끔 | 단일 해상도 배포면 불필요. 거리 변화는 기본 `scale` 증강으로 대응 |
| 본 학습 전 | `fraction=0.1` 리허설 | 경로 오타로 학습을 통째로 날리는 사고 방지 (성능 판단용 아님) |

학습 코드:

```python
from ultralytics import YOLO

# 0) 리허설 — 설정이 돌아가는지만 확인
YOLO("yolo26n.pt").train(data="byeol.yaml", fraction=0.1, epochs=3, imgsz=640)

# 1) 본 학습 — 컬러 영상
model = YOLO("yolo26n.pt")
model.train(
    data="byeol.yaml", imgsz=640,
    epochs=300, patience=15,
    batch=-1, cache=True,
    freeze=10,
)
```

### 3.5 학습 중 문제가 생기면

| 증상 | 먼저 확인할 것 |
|---|---|
| 아무것도 예측하지 못함 | ① `conf=0.1`로 낮춰 박스가 나오는지 (나오면 모델은 살아 있고 성능 부족) ② `data.yaml` 경로와 라벨 개수 — 경로가 틀려도 에러 없이 라벨 0개로 학습이 끝남 |
| mAP가 일찍 정체 | 에폭을 늘리지 말고 데이터를 봄: 약한 장면 데이터 보강, 라벨 품질 점검 |
| 새로 학습한 뒤 다른 장면을 못 찾음 | 치명적 망각 방지: 새 데이터만이 아니라 기존 데이터와 **합쳐서** 학습 |

클래스가 하나뿐이라 클래스 불균형(`cls_pw`) 문제는 해당하지 않습니다. 대신 **장면 불균형**(서 있는 장면만 많고 누운 장면이 적음)을 같은 관점으로 보고, 약한 장면의 데이터를 의도적으로 늘립니다.

## 4. 검증 계획

### 4.1 가장 중요한 원칙: 같은 영상을 학습과 검증에 나눠 넣지 않는다

연속된 프레임은 거의 같은 사진입니다. 한 영상의 프레임을 학습용과 검증용에 섞어 넣으면, 모델이 **외운 것을 맞히는 것**이라 mAP가 실제보다 높게 나옵니다.

- **녹화 세션(날짜) 단위**로 학습 / 검증 / 시험을 나눕니다.
- **시험(test) 세트는 학습과 설정 조정에 한 번도 쓰지 않고**, 마지막에 한 번만 평가합니다.

### 4.2 결과표: 클래스 대신 장면별로 본다

클래스가 `person` 하나뿐이라 클래스별 줄이 의미가 없습니다. 대신 **장면별로 검증 세트를 나눠** 같은 표를 만듭니다.

| 장면 | Images | Instances | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|---|
| all | | | | | | |
| 서 있음 · 이동 | | | | | | |
| 앉음 | | | | | | |
| **누움** | | | | | | |
| **가려짐** (조리대 · 식탁) | | | | | | |
| **저녁 조명 · 역광** | | | | | | |
| **TV 켜짐** (오검출 확인) | | | | | | |

### 4.3 어떤 숫자를 중요하게 보는가

| 지표 | 의미 | 별일없지에서의 비중 |
|---|---|---|
| **Recall (재현율)** | 있어야 할 사람 중 몇 명을 찾았나 | **1순위.** 사람을 놓치면 "시야 밖"으로 기록되고, 오래 누운 상태를 놓치는 것이 가장 위험한 실패 |
| **Precision (정밀도)** | 사람이라고 한 것 중 몇 개가 맞았나 | **TV 장면에서 집중 확인.** TV 속 사람을 잡으면 "활동 중" 오기록 |
| **mAP50** | IoU 0.5 기준 AP의 평균 | 주 지표. 박스는 관절 추정용 crop과 발 위치 추정에만 쓰므로 IoU 0.5면 충분 |
| **mAP50-95** | IoU 0.5~0.95, 10단계 평균 | 참고 지표. 박스 위치가 아주 정밀할 필요는 없음 |

### 4.4 신뢰도 임계값(conf)은 측정으로 정한다

**검증할 때는 conf를 거의 0(0.001)**으로 두고 Precision-Recall 곡선 전체를 그립니다. 추론 기본값 0.25를 그대로 쓰지 않고, 곡선에서 **Recall을 우선하면서 Precision이 크게 무너지지 않는 지점**을 골라 실제 운영값으로 정합니다. TV 오검출은 conf를 올리는 대신 **제외 영역(후처리)과 배경 이미지 학습**으로 먼저 줄입니다.

```python
best = YOLO("runs/detect/train/weights/best.pt")
best.val(data="byeol.yaml", split="val", conf=0.001)   # PR 곡선 전체
best.val(data="byeol.yaml", split="test", conf=0.001)  # 최종 1회
```

### 4.5 결과표 진단

| 결과 패턴 | 해석 | 조치 |
|---|---|---|
| P 높고 R 낮음 | 확실한 것만 잡고 사람을 놓침 | conf 낮추기, 약한 장면(누움·가려짐) 데이터 보강 |
| P 낮고 R 높음 | 사람이 아닌 것까지 잡음 | TV·거울 배경 이미지 추가, 제외 영역 확인 |
| mAP50 높고 mAP50-95 낮음 | 찾기는 하지만 박스가 느슨함 | 별일없지에서는 대부분 허용. 발 위치 오차가 크면 라벨 품질 점검 |
| 특정 장면만 낮음 | 그 장면의 데이터 부족 | 해당 장면 데이터를 늘려 재학습 |

### 4.6 학습의 효과를 증명하는 비교

같은 검증·시험 세트에서 아래 세 줄을 나란히 둡니다.

| 모델 | 누움 R | 가려짐 R | 저녁 R | TV P | 처리 속도 |
|---|---|---|---|---|---|
| 사전학습 그대로 (`yolo26n.pt`) | | | | | |
| 파인튜닝 후 | | | | | |
| 후보 B (`yolo26n-pose`) | | | | | |

파인튜닝 후 약한 장면의 Recall이 올랐다면, 그것이 학습이 필요했다는 근거가 됩니다. 오르지 않았다면 모델이 아니라 데이터나 카메라 위치를 다시 봅니다.

### 4.7 제품 단위 검증: 모델 점수 ≠ 제품 성능

mAP가 높아도 보호자 앱에 틀린 기록이 뜨면 의미가 없습니다. 최종 출력인 **생활 이벤트 단위**로 한 번 더 검증합니다 (PRD 3장 KPI).

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 위치(Zone) 판정 정확도 | ≥ 90% | 라벨링한 시나리오 영상의 구간 대비 |
| 자세 분류 정확도 | ≥ 90% | 같음 |
| 상태 떨림 (1분 미만 왕복 전환) | 시간당 ≤ 1회 | 연속 구동 로그 |
| 처리 속도 | ≥ 5 FPS | 노트북 실측, Raspberry Pi는 대여 가능 시 실측 |
