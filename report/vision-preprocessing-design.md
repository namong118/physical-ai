# 별일없지 Edge Vision 전처리 설계

> 문서 버전 v1.1 · 작성일 2026-10-07 (v1.1: 키포인트 평활화를 EMA에서 One-Euro 필터로 변경)
> 대상: 별일없지 Physical AI PoC의 Edge Vision 파이프라인 (카메라 → Raspberry Pi → 사람 검출 → Pose → 상태 판단)
> 상태: **구현 전 설계.** 각 단계는 Phase A(저장 영상 검증)에서 효과를 측정한 뒤 유지 여부를 결정한다.

---

## 0. 전제 조건

| 조건 | 전처리에 주는 영향 |
|---|---|
| 고정 카메라, 1인 가구 | 카메라 움직임 보정 불필요, 사람 1명만 추적 |
| 거실·주방이 트인 구조, 광각 카메라 | 사람이 화면에서 작게 잡힘 → Pose 정확도 저하 |
| 거실: 창문 역광(낮), 실내 조명(저녁), TV | 조도 변화가 크고 TV 속 사람이 오검출될 위험 |
| 주방: 조리대·아일랜드 | 하체(발목)가 자주 가려짐 |
| 침실: 야간 IR 카메라 | 흑백 영상, 노이즈 많음, 이불에 몸이 가려짐 |
| Raspberry Pi (CPU 제한) | 프레임당 연산 최소화 필요 |
| 사전학습 모델 사용 (YOLO, MediaPipe) | 학습 분포에서 크게 벗어나는 보정은 오히려 성능 저하 |
| 판단 단위가 분 단위 상태 | 프레임 정밀도보다 시간적 안정성이 중요 |
| 원본 영상 저장·전송 금지 | 모든 처리는 메모리 안에서, 디버그 녹화는 개발 모드로 분리 |

판단은 **위치(Zone) + 자세** 두 축으로 한다.

- 위치: 주방 / 거실 / 식탁 / 소파 / 침대 / 시야 밖
- 자세: 서기·이동 / 앉음 / 누움

## 1. 공통 파이프라인

| 순서 | 단계 | 기법 | 적용 조건 | 이유 |
|---|---|---|---|---|
| 1 | 캡처 설정 | 카메라에서 해상도·FPS·노출 고정 | 항상 | 소프트웨어 보정보다 싸고 화질 손실 없음 |
| 2 | 프레임 샘플링 | 30fps 중 5~10fps만 처리 | 항상 | 판단 단위가 분 단위. Pi 부하를 가장 크게 줄임 |
| 3 | 검출용 축소본 | 640px 정도로 축소, **원본은 보존** | 항상 | 검출은 축소본으로 충분, 원본은 Pose crop에 사용 |
| 4 | 밝기 보정 | 감마 LUT 또는 LAB L 채널 CLAHE | 어둡거나 역광일 때만 | 검출 실패를 막되, 정상 조도에선 모델 입력 분포를 해치지 않게 |
| 5 | 사람 검출 | YOLO (letterbox·정규화는 라이브러리 내부) | 항상 | 직접 리사이즈·정규화를 중복하지 않음 |
| 6 | 검출 필터 | 신뢰도·크기 기준, **제외 영역**(TV·거울·액자) | 항상 | 거실 TV 속 사람, 거울 반사 오검출 제거 |
| 7 | 2단계 Pose | 원본에서 사람 영역 crop(여백 포함) → RGB 변환 → MediaPipe | 사람 검출 시 | 광각 화면의 작은 사람도 관절을 정확히 잡기 위해 |
| 8 | 키포인트 정리 | visibility 낮은 관절 제외, **One-Euro 필터** 평활화 (속도는 박스 높이/초로 정규화) | 항상 | 가려진 관절의 튀는 값 제거. 느릴 땐 떨림을 지우고 빠를 땐 지연 없이 따라감 |
| 9 | **발 위치 계산** | 양 발목 중간점, 가려지면 엉덩이 기준 아래로 보정 | 항상 | 위치 판정의 기준점. 몸 중심은 원근 때문에 실제보다 뒤쪽에 찍힘 |
| 10 | **Zone 판정** | 설치 시 지정한 바닥 기준 다각형 + `cv2.pointPolygonTest` | 항상 | 주방·거실·식탁·소파·침대를 이미지 마스크 없이 좌표로 판정 |
| 11 | 상태 확정 | 위치 + 자세 + 체류 시간 + 히스테리시스 | 항상 | Zone 경계·자세 경계에서의 떨림 방지 |

### 핵심 포인트

- **7번 2단계 Pose:** 축소본으로 사람 위치를 찾고, 원본 해상도에서 그 영역만 잘라 Pose에 넣는다. 3번에서 원본을 보존하는 이유다.
- **9번 발 위치:** 주방은 조리대 때문에 발목이 자주 가려지므로, 엉덩이 기준 보정이 주방 판정 정확도를 좌우한다.
- **10번 Zone:** 이미지를 가리는 마스크가 아니라 추론 후 좌표로 판정한다.

### 위치 + 자세 조합 예

| 위치 | 자세 | 체류 | 상태 |
|---|---|---|---|
| 주방 | 서기·이동 | N초 이상 | 주방 활동 |
| 식탁 | 앉음 | N분 이상 | 식탁 체류 |
| 소파 | 앉음 | N분 이상 | 휴식 |
| 거실 | 서기·이동 | — | 활동 |
| 침대 | 누움 | 장시간, 낮은 움직임 | 침대 휴식 (수면 추정) |
| 침대 밖 바닥 | 누움 | N분 이상 | 확인 필요 |
| — | 사람 없음 | 일정 시간 | 시야 밖 (외출 아님) |

> "시야 밖"은 외출로 판정하지 않는다. 외출은 현관 센서가 근거일 때만 추정한다.

## 2. 카메라별 차이

| 항목 | 거실·주방 카메라 | 침실 카메라 (IR) |
|---|---|---|
| 주요 조도 문제 | 낮 창문 역광, 저녁 실내 조명 | 야간 저조도 |
| 밝기 처리 | 조건부 감마 또는 CLAHE (L 채널) | 흑백 → 3채널 복제 + CLAHE (야간 항상) |
| 오검출 원인 | TV, 거울, 액자 | 이불 형태, 옷걸이에 걸린 옷 |
| 가림 문제 | 조리대·식탁에 하체 가림 | 이불에 몸 대부분 가림 |
| Zone | 주방, 거실, 식탁, 소파 | 침대, 침대 밖 바닥 |
| 핵심 판단 | 위치 + 자세 → 활동·휴식·주방 활동·식탁 체류 | 침대 Zone + 누움 + 낮은 움직임 → 침대 휴식 |

침실은 이불 때문에 관절이 보이지 않는 시간이 길다. 키포인트 외에 **사람 박스의 위치, 가로·세로 비율, 박스 내부의 움직임 양**을 함께 보는 보조 판정이 필요할 가능성이 높다 (로드맵 2단계 검증 항목).

## 3. 순서의 근거

1. **버리는 연산을 먼저 한다.** 샘플링 → 축소를 앞에 두면 뒤의 모든 연산이 처리하는 프레임 수와 픽셀 수가 함께 줄어든다.
2. **되돌릴 수 없는 손실은 늦게 한다.** 검출은 축소본으로, Pose crop은 원본으로 한다. 축소본에서 crop하면 2단계 처리의 이점이 사라진다.
3. **검출을 살리는 보정은 검출 앞에, 단 조건부로.** 항상 보정하면 정상 이미지의 분포가 바뀌어 성능이 오히려 떨어질 수 있다.
4. **색 변환은 한 번만, 작은 이미지에.** OpenCV는 BGR로 읽고, Ultralytics YOLO는 numpy 입력을 BGR로 가정하며, MediaPipe는 RGB를 요구한다. 그래서 Pose 직전 crop 이미지에만 변환한다. 라이브러리 버전별 입력 규칙은 구현 시 문서로 확인한다.
5. **Zone은 전처리가 아니라 추론 후 판정이다.** 이미지를 Zone으로 가리면 경계에 걸친 사람의 몸이 잘려 검출과 Pose가 망가진다.
6. **떨림은 두 번 막는다.** 키포인트 평활화(8번)와 상태 히스테리시스(11번)가 "상태 떨림" KPI를 결정한다. 8번에 EMA 대신 One-Euro 필터를 쓰는 이유는, EMA는 떨림 제거를 강하게 할수록 움직임을 늦게 따라가지만 One-Euro는 관절 속도에 따라 강도를 바꿔 두 가지를 함께 얻기 때문이다.

## 4. 사용하지 않는 기법

| 기법 | 이유 |
|---|---|
| 렌즈 왜곡 보정 | 비용이 크고, Zone을 원본 화면 위에 그리면 같은 효과. Zone 판정 오류가 확인될 때만 도입 |
| 강한 노이즈 제거 (Non-local Means 등) | Pi에서 너무 느림. 노출·IR 조명 조정으로 먼저 해결 |
| 배경 차분 | YOLO가 사람을 직접 찾으므로 불필요하고 조명 변화에 약함 |
| RGB 채널별 히스토그램 평활화 | 색 왜곡. 밝기 보정은 L 채널에만 |
| 샤프닝 | 노이즈 증폭, 모델 학습 분포와 달라짐 |
| 자동 공간 인식 | Zone은 설치 시 사람이 지정하는 쪽이 정확하고 설명 가능 |
| 얼굴 블러 | 원본을 저장·전송하지 않으므로 처리 경로상 불필요. 디버그 녹화를 남길 때만 고려 |

## 5. 센서 신호 전처리 (로드맵 3단계 대비)

| 대상 | 기법 | 이유 |
|---|---|---|
| PIR | 쿨다운 30초 이상 (현재 5초는 개발값) | 이벤트 폭주 방지, 이벤트 조회 창 문제 완화 |
| 문 센서 | 디바운스 | 문이 덜컹거릴 때 열림·닫힘이 연속으로 찍히는 것을 하나로 묶음 |
| 화장실 | "문 열림 → PIR 감지"를 한 번의 입실로 묶기 | 입실·퇴실과 체류 시간 계산의 기준 |
| 현관 | "문 열림 → 이후 집 안 활동 없음"을 외출 후보로 묶기 | 손님 방문과 외출 구분 |

## 6. 검증 방법

1주차에 녹화할 영상을 **조도**(낮·저녁·역광·야간 IR)와 **구역**(주방·거실·식탁·소파·침대)별로 나누고, 단계를 하나씩 켜고 끄며 비교한다.

| 단계 | 측정 지표 |
|---|---|
| 밝기 보정, IR 처리 | 조도별 사람 검출률 |
| 2단계 crop | 키포인트 평균 visibility, 자세 분류 정확도 |
| 발 위치 보정 (엉덩이 기준) | 주방 구간의 Zone 판정 정확도 |
| 제외 영역 | TV를 켠 영상의 오검출 수 |
| 평활화, 히스테리시스 | 시간당 상태 떨림 횟수 |
| One-Euro vs EMA | 상태 떨림 횟수 + 상태 전환 지연 |
| 전체 | Raspberry Pi에서의 처리 FPS |

**원칙:** 효과가 숫자로 확인되지 않는 단계는 뺀다. 이 표의 측정 결과가 발표 자료의 "전처리 선택 근거"가 된다.
